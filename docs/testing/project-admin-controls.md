# Project administrator controls — acceptance

Catalogue: IT-PROJECT-006 (manual project state and closure), IT-WORKFLOW-008 (individual administrator workflow bypasses).

## Business decisions (2026-11-01)

- Only an actual `admin` with `projects.override` may set/clear manual project state, manually close or reopen, or explicitly create/revoke a project workflow bypass. A custom office profile without that sensitive permission and non-admin/employee accounts cannot do so, including direct HTTP requests. Ordinary project editing cannot mass-assign execution fields. Existing ordinary, source-controlled workflow actions stay available under their normal permissions.
- Status and progress overrides are independent, can be 0–100 inclusive, and persist until an authorised administrator clears them. The workflow still calculates its own progress and stage; office screens distinguish calculated from administrator-set values. A reason, actor, time and before/after state are auditable. Explicit closing/reopening uses closure controls rather than setting a financially closed label through the status dropdown. A manual status/progress is presentation/state only: it never changes underlying steps, approvals, ledger or financial documents.
- Administrators may manually close a project despite unfinished workflow controls and outstanding money, with an explicit reason and risk acknowledgement. This is labelled **Manually closed**, never falsely called financially complete. Record an immutable financial/source snapshot, all open operational steps, actor and time. Keep invoices, bills, payments and balances active and visible; do not fabricate completion, approval or settlement. Do not silently issue close-out feedback merely because of a manual close. Reopening preserves closure history and resumes any stored manual status; manual status and progress remain until explicitly cleared.
- Each project workflow rule can be individually bypassed by an authorised administrator, with an explicit reason and a record that does not falsify the source. Existing gate overrides stay tied to a current evaluation and existing approval overrides to an exact file version. When the workflow has no evaluation or client-approval request, a recorded missing-source bypass is available for that specific step; a new source evaluation/request supersedes it. The finance-closure rule uses the explicit manual closure decision and immutable snapshot. Revocation must not reapply a stale evaluation over a newer one. Linked project actions honor the current, auditable gate decision; bypass does not override general input validation, ownership, concurrency integrity, unrelated ERP rules or access control.
- Include ordinary and restricted access, validation, zero/100, repeated recalculation, no-workflow/legacy project, stale and cross-project IDs, source changes and revocation, approvals with and without a request, every individual workflow step, financial outstanding, closure/reopening, rollback protection, regular workflow regression and separate calculated/published UI checks. Use fictional data and no live external delivery.
